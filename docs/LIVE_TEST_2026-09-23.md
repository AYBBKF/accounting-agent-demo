# Dossier fictif envoyé le 23 septembre 2026

Le test Gmail a porté sur l'image déjà déployée, avant ces modifications.
Un ZIP de huit membres a été envoyé pour une nouvelle société fictive.
Les identités et les identifiants légaux du scénario sont fictifs.

| Cas | Résultat observé |
| --- | --- |
| Création du dossier | Classeur et dossier Drive distincts créés automatiquement |
| Deux achats PDF et un achat JPEG | Trois lignes, TTC total 2 160 MAD |
| Vente PDF | Une ligne, TTC 2 400 MAD ; nom client tronqué, anomalie confirmée |
| Avoir fournisseur | Une ligne, TTC −120 MAD et trois lignes de journal inversées |
| Devis | Classé dans les documents commerciaux, hors journal |
| Facture incohérente | Écart 150 MAD signalé dans la quarantaine, sans écriture comptable |
| Copie exacte renommée | Aucune deuxième ligne d'achat ni de journal |
| Journal | 15 lignes ; débit = crédit = 4 680 MAD |
| Archives | ZIP original et sept documents distincts trouvés dans Drive |
| Notification | Résumé et alerte acceptés par Telegram selon les logs serveur |
| Relectures | Au moins trois cycles successifs sans changement ni renotification |
| Société existante | Huit plages A1:Z1000 comparées en mode FORMULA, inchangées |

Le test n'est pas entièrement vert : un onglet de sauvegarde de quarantaine
du modèle contenait encore des données historiques dans le nouveau classeur.
Le nettoyage des copies neuves inclut maintenant ces sauvegardes connues et
les onglets BOT, avec des plages sans limite de lignes. Cela ne dispense pas
de fournir un modèle vierge vérifié, y compris les onglets de configuration.
Les classeurs déjà initialisés ne sont jamais nettoyés automatiquement.

Le nom « CLIENT NOVA DEMO SARL » était raccourci en « NOVA DEMO SARL ». Le
nettoyage du nom retire désormais un préfixe de rôle seulement avec un
séparateur explicite. Des tests protègent aussi les noms tels que CLIENTEL.

Google refusait également la validation NOT_BLANK utilisée pour l'infobulle,
sans bloquer la quarantaine. Elle est remplacée par une formule toujours vraie,
non bloquante, prise en charge par la [validation Google Sheets](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/other#ConditionType).

Les preuves détaillées restent dans le dossier opérateur local ; aucun contenu
d'une société existante ni identifiant de notification n'est publié ici.
Cette vérification ne couvre ni tous les classeurs, ni un relevé bancaire, ni
un arrêt/reprise du serveur. Elle ne constitue pas un test du nouveau digest,
qui doit être validé sur un déploiement isolé avant remplacement en production.
